# Break-glass: аварийный доступ

## Что это

Break-glass — единственная учётная запись, которая позволяет войти в
систему, когда все SUPERVISOR'ы потеряли доступ. Это не «резервный
админ», это **аварийный молоток в стеклянной коробке**.

## Когда применять

Только в ситуациях, когда:

- **все** SUPERVISOR'ы потеряли доступ к системе
  (забыли пароль + потеряли MFA + потеряли токены);
- система находится в состоянии, когда невозможно вернуть
  SUPERVISOR'а через обычные каналы;
- у вас есть **физический доступ** к серверу (KVM/ILO/VM-консоль).

## Когда НЕ применять

- «SUPERVISOR в отпуске, я хочу по-быстрому получить доступ» — нет.
- «SUPERVISOR уволился, но его пароль у нас есть» — нет.
- «Мне лень ждать, пока SUPERVISOR подтвердит инвайт» — нет.

Каждое включение break-glass:

- пишет громкий аудит (`BREAK_GLASS_ENABLED`, `BREAK_GLASS_USED`);
- уведомляет всех активных SUPERVISOR'ов по email;
- логируется в stderr с уровнем `WARNING`.

## Модель безопасности

| Свойство | Значение |
| --- | --- |
| Включение | только `manage.py` с физического доступа |
| Выключение | автоматическое через N часов, либо вручную через `manage.py` |
| Проверка «живых» SUPERVISOR'ов | обязательна; обход — `--force` |
| AAL сессии | сразу AAL3 |
| Уведомление SUPERVISOR'ов | email + audit |
| Аудит каждого входа | `BREAK_GLASS_USED` с IP и user-agent |
| Пароль | 24 символа, хранится в recovery kit в физическом сейфе |

## Процедура

### Разовая инициализация (при bootstrap)

При завершении setup-фазы автоматически:

1. Создаётся учётка `break-glass` (неактивна).
2. Генерируется пароль 24 символа + recovery codes.
3. Recovery kit (PDF + TXT) кладётся в `/var/lib/postinstall/recovery/`.
4. Администратор **обязан** скачать kit и положить в физический сейф.
5. Файл на сервере можно удалить после скачивания.

### Включение (аварийная ситуация)

С физического доступа к серверу:

```bash
sudo -u postinstall python manage.py break_glass enable \
    --reason "все SUPERVISOR'ы потеряли доступ, восстановление"
```

Если система отказывает «есть живые SUPERVISOR'ы» — это защита.
Проверьте, действительно ли они недоступны. Для обхода:

```bash
sudo -u postinstall python manage.py break_glass enable \
    --reason "подтверждено руководителем ИБ" --force
```

### Вход

1. Открыть `/accounts/login/` с консоли сервера (не по сети).
2. Логин: break-glass.
3. Пароль: из recovery kit.
4. Сессия сразу AAL3.

### Восстановление нормального доступа

1. Войти break-glass.
2. Создать нового SUPERVISOR'а через `/access/setup/` или инвайт.
3. Второй SUPERVISOR создаёт ещё одного (по правилу ≥2).
4. Выключить **break-glass**:

    ``` bash
    sudo -u postinstall python manage.py break_glass disable
    ```

### Пересоздание пароля

Если пароль утерян или скомпрометирован:

```bash
sudo -u postinstall python manage.py break_glass reset-kit --out /tmp/
```

Создаст новую учётку с новым паролем. Старый **recovery kit** — уничтожить.

### Ограничения IP (опционально, если включено)

Если в `AUTH_BREAK_GLASS_ALLOWED_IPS` задан список `CIDR` — break-glass
принимается только с этих адресов. По умолчанию — любой IP
(но рекомендуется ограничить **127.0.0.1/32**).

### Аудит

Все события break-glass в /admin/access/authauditlog/:

- `BREAK_GLASS_ENABLED` — включение (с причиной и флагом **force**).
- `BREAK_GLASS_USED` — каждый вход.
- `BREAK_GLASS_DISABLED` — выключение (ручное или авто).

Фильтр в админке: `event__startswith="break_glass"`.
